# Boundary evidence reliability audit

## Candidate scope

Unpublished candidate 0.2.0rc1, prepared on 5 November 2026.
Base commit 112ed6904f151f27cae635d77c43a36124df76aa passed 196 tests.
Seventeen additional synthetic checks reproduced failures before repairs. The
original test file and failing logs are preserved outside the working checkout.
The copied regressions retain their original assertions. This pass prepares a
draft pull request; independent review, merge and publication remain separate.

## Confirmed issues and repairs

| Area | Reproduction | Correction |
| --- | --- | --- |
| Ambiguous JSON | Repeated keys silently selected the last value; nonfinite numbers were accepted. | Reject duplicate keys, NaN, Infinity and overflowing numeric literals. |
| Resource limits | Deep evidence could raise a traceback; oversized files and process output were read without bounds. | Limit JSON and each captured stream to 1 MiB, JSON depth to 64, and terminate the owned process group when capture limits are detected. |
| Mandatory measurements | A skipped filesystem or child-process check could still count as complete evidence. | Reject mandatory skips in new probe payloads; classify older reports containing them as incomplete during comparison. |
| Synthetic file safety | Read fixtures and result files could follow a substituted symlink. | Use shared standalone regular-file helpers, refuse redirects/hardlinks/special files, bound canary reads and create markers exclusively. |
| Scope interpretation | A configured remote Docker transport appeared as an absent Unix socket, potentially satisfying a deny policy. | Mark unsupported transport coverage skipped, which does not satisfy required denial. |
| Demo isolation | The account-free demo disabled TCP but still discovered and could connect to real host Unix sockets. | Disable socket discovery and connection as well; expose an explicit no-sockets option for other modes. |

The generated probe embeds the same standard-library file helpers used by the
collector. POSIX traversal uses directory descriptors with no-follow flags and
search-only access where available; it does not need directory-listing access.
If safe parent validation cannot be established, the result is inconclusive,
not proof of a denied capability. Windows uses reparse-point checks with the
existing documented weaker concurrent-path guarantees.

## Compatibility

CLI command names and JSON report schema version 1 remain. The new no-sockets
option is additive. Legitimately disabled environment, network and socket probes
still report skipped and produce partial coverage. A policy requiring a denied
capability fails when that capability was only skipped. Missing or invalid
evidence returns CLI status 2, policy failure returns 1, and a completed
measurement with no failed policy returns 0. A high exposure score alone is not
a policy failure, so an unsandboxed demo can correctly exit 0.

Reports with duplicate keys, invalid finite values, excessive nesting or size,
and evidence files reached through unsafe links are now rejected. A mandatory
skip in an older report is treated as lost evidence rather than a passing diff.
Use fresh, directly named single-link regular files. Human-selected parent
aliases for configuration/report inputs are resolved; prepared lab evidence
requires non-redirected components.

Each output stream is captured through a temporary spool and checked at intervals
of at most approximately 50 ms while the runner is active. Returned content is
bounded and any overflow invalidates collection, including an otherwise valid
retained result file. This is not a hard operating-system disk quota: a fast
writer can temporarily exceed the threshold between checks. Timeout and existing
owned-process-group cleanup remain. Windows detached-child limitations remain.

Raw agent transcripts are not included in normal reports. Run-local HMAC keys
remain integrity checks, not a defense against an agent that controls the lab.
The synthetic child interpreter uses isolated, no-site startup to avoid unrelated
Python startup hooks; the real coding-agent process retains its configured runtime.
No permission bypass, trust override, sandbox disablement or elevation flag was
added to an agent adapter.

## Verification and limitations

The local implementation suite contains 271 tests, including the 17 original
reproductions and valid positive controls. The eight-case showcase separates a
real unsandboxed synthetic probe from controlled evidence mutations. No paid
inference, real credential access or real Docker/SSH-agent protocol interaction
was used. The normal tests isolate homes and stub host service baselines.

Codex CLI 0.148.0 was present and its version/help syntax was checked without
starting a model session. Claude Code and Gemini CLI were not installed. Their
command construction and config handling are fixture-tested, with official CLI
documentation checked. None is claimed to have a fresh end-to-end live boundary
measurement from this pass.

An existing contributor PR #4 changes only the process-cleanup test helpers to
isolate Python startup hooks. It was inspected and left open and unmerged. Its
branch and substantive patch are untouched. This candidate retains the same
cleanup assertions and does not absorb that contribution without attribution.

The current PyPI distribution 0.1.2 points to this repository. The publication
trigger file remains unchanged. Release CI is strengthened to require the exact
commit's full test matrix and installed-package checks, and to refuse candidate
versions. No package upload or release tag is authorized by this implementation pass.

## Hosted portability observation

The first hosted macOS Python 3.12 run exposed a test assumption: that interpreter
build does not expose search-only directory-open flags. The production helper
already returned an inconclusive safety-validation error for a search-only parent,
rather than reporting a denial. The test now checks the supported behavior for
each interpreter. A separate regression removes the flags deliberately to verify
this fallback. No numeric platform flag is guessed and no safety check is bypassed.
The original failed job log is retained with the implementation evidence.
